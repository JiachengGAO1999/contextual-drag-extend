## 为什么换这个问题

旧Game24实验中，题目规则完全给定。失败反馈可能提供有用的计算结果，
但通常没有揭示原题之外的隐藏环境事实。不能直接将“删历史后恢复”
推广成需要从环境错误中学习的任务上的通用方案。

不过，这个宽泛观点也已有工作：

- [Feedback That Backfires](https://arxiv.org/html/2608.23651v1) 已拆分失败
  动作表面形式与错误消息，比较抽象记录和删除记录；明确指出抽象可能
  丢失修复所需信息。仅“保留诊断、删除失败动作”不是新方法。
- [CORE](https://arxiv.org/html/2609.39069v1) 已用经认证的冲突指导回退、
  缓存并剪枝，含Qwen3-8B与24-Game。仅“学习失败约束”不是新方法。
- [GeoPlanner §4.3](https://openreview.net/pdf/e192630e67209fc1f7fedb0dea387900edaa975f.pdf)
  已保留验证通过的前缀并重规划后缀。保留正确前缀本身也不是新贡献。
- [GPT-4 Doesn't Know It's Wrong](https://arxiv.org/abs/2310.12397) 已比较
  pass/fail、首个错误及全部错误等反馈。仅改变反馈详细程度也不是新检验。

这里值得进一步评估的具体问题是：**压缩失败记录时，是否尊重检查器
选择、执行和报告检查项的规则？相同错误消息未必代表相同证据。**
这是统计充分性和反馈语义问题；概念本身并非新的数学发现。潜在研究
价值取决于是否发现模型或现有上下文管理方法的系统性失效，以及能否
据此预测何时该保留哪些历史，而非仅增加一个提示基线。

## 一个可以精确检查的例子

有四个角色A/B/C/D和四个槽位red/blue/green/yellow，正确分配是一个
隐藏的一一对应。已知所有24种对应等可能。旧方案是：

`A→red, B→blue, C→green, D→yellow`。

检查器报告 `C→green 不通过`。这句话有两种不同的解释：

1. **按A/B/C/D顺序检查，遇到首错就停。**那么A→red、B→blue已通过；
   C不能green。一一对应又使C必须yellow、D必须green：只剩1种可能。
2. **事先独立随机选一个角色，只检查该角色。**若选中C并报错，则
   A/B完全没有被检查；仍有18种可能。不能把旧方案前两项当成正确。

两者的失败动作和可见错误句可以相同，但检查规则不同，所以可推导
的事实不同。检查规则须在问题说明中明确，不能要求模型猜隐藏协议。

第一种情况下，仅保存“C不能green”丢掉了前面通过的信息；完整旧方案
则还包含没有执行过的D→yellow。一个正确的信息摘要应保存：

`已通过：A→red、B→blue；已否定：C→green；D的旧分配未经检查。`

这份摘要与完整的首错记录允许完全相同的隐藏世界，并未额外给正确
答案。第二种规则下，摘要只能保存C不能green，不能认证A/B。
这个结论不适用于“不报告就代表通过”不成立的检查器；例如没有错误
日志通常不足以证明任意代码的正确性。

## 若继续，什么结果才有研究价值

首先区分两类差异：完整记录与有损摘要差异可能只是信息丢失；完整
记录与**确证信息等价**摘要之间的差异，才有资格解释为模型处理表达
方式的差异。摘要更容易理解仍是竞争解释，不能直接归为神经重置。

潜在的新预测是：反馈报告规则应系统性改变有效记忆的内容；固定
“只留错误”或“保留失败前缀”的策略不能在两种规则下都正确。需要
检验的是模型是否根据已知规则选择性保留证据，而非重复证明旧方案
会被复用。若最终只有显式列出事实更容易做题，仍不足以成为ICLR主张。

目前没有该预测的模型证据，也未完成足以证明新颖性的文献核对。
不直接把这三个逻辑类别扩成新的GPU小矩阵。进一步推进前应选定
具有真实检查语义的独立任务，并说明新结果如何超出上述相邻工作。
原共享24 GPU小时预算不变，本预览不会排队或启动模型实验。

## 真实检查器核对：不能认证文字前缀，也不能把局部错误泛化

新增入口：`python scripts/audit_sqlite_feedback_semantics_20261012.py`。
输出同目录的`sqlite_semantics.json`。只建立一次性内存数据库，不访问
项目或外部数据库，不调用模型。当前本地SQLite版本3.33.0。

限定只有一个表和SELECT列列表、四个候选列中恰有两个存在时，6种
schema×24种列顺序的144次真实执行均先报告列表中第一个不存在的列。
直接用各schema的实际报错计算可能世界集合，均与正确前缀摘要一致；
72个枚举记录中只留报错列会丢信息。这仍是少数对称逻辑类别，不是
144道模型测试，更不是跨版本的SQLite规范保证。

添加其他子句后，通用文字前缀推断立即失效。实际表含alpha、beta：

```sql
SELECT gamma FROM resources WHERE alpha>0 LIMIT delta;
-- 实际报告：no such column: delta
```

虽然gamma在报错的delta之前出现，它也不存在。这证明不能仅按报错
位置将此前文字标记为已通过。名称解析通过更不等于运行或语义正确。

还有一个更直接的作用域反例，同一个真实表含alpha：

```sql
SELECT alpha FROM resources LIMIT alpha;
-- 实际报告：no such column: alpha

SELECT alpha FROM resources;
-- 正常执行
```

所以`no such column: alpha`不能不看失败查询就改写成“表里没有alpha”。
它在这个使用位置不可见，不代表全局不存在。输出还保留ORDER BY可
使用而LIMIT不可使用同一个SELECT别名的配对例子。

这些都是检查器的真实行为，不是已经观察到的模型误解。它们**否定
直接推出通用前缀保留方法**，也要求修改候选问题：负反馈能否被模型
保留在正确的对象、位置和条件下，而非泛化成无条件禁止？

如果后续只有“补充SQL解释后模型更容易答对”，依旧不是有力贡献。
有价值的模型证据应同时显示：准确接受原失败的局部诊断；却将诊断
错误迁移到仍有效的用法；保持作用域的信息等价变换能减少这种迁移，
同时仍拒绝原非法用法。它与重复旧错式不同，但目前尚无模型证据，
没有新颖性保证，也没有足够理由自动启动新GPU实验。
