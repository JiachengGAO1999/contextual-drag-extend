# 反馈候选方向：新增文献后的取舍（2026-10-12）

结论：目前不能将“局部反馈被全局化”或“报告规则影响证据”直接
升级为本项目新主线。两个宽泛命题都已有重要相邻工作。以下是
对候选的收敛判断，不是模型结果、working MVP或GPU执行授权。

## 本轮实际新增的文献边界

1. [RLVF，ICML 2024](https://proceedings.mlr.press/v235/stephan24a.html)
   明确研究模型将语言反馈用于不相关情境的过度泛化，方法使用
   合成偏好数据与受约束优化。仅发现局部禁令被扩大，不足以构成
   我们的新增贡献；换成SQL作用域也不能自动改变这一判断。
2. [Hypothesis generation and updating in large language models](https://arxiv.org/html/2605.05851v1)
   已改变提示中的强／弱采样叙述，并测量后验预测、假设评估和
   假设生成。正文§3.2报告采样叙述会改变拟合行为。因此不把
   “LLM对证据采样机制有偏差”作为未研究过的问题，也不预设
   模型完全忽略采样规则。该工作是预印本，不据此声称结论普遍。
3. [Formalizing Learning from Language Feedback，ICML 2026](https://proceedings.mlr.press/v306/xu26ao.html)
   已给出语言反馈的信息与学习复杂度框架及HELiX算法。
   本轮另读[早期v1正文](https://arxiv.org/html/2506.10341v1)§2：
   反馈由动作条件下的分布产生，而非仅一个孤立标签。不能把
   “失败信息可用于约束假设空间”或“需要考虑反馈生成分布”
   当作新理论；未逐页核实最终版本与v1一致。

之前记录的Feedback That Backfires、CORE与前缀保留工作继续适用。
这些文献不证明本候选一定没有价值；它们改变的是新贡献所需证据。

## 尚值得评估的具体问题

在同一个求解模型、相同失败方案和可见报错下，只改变公开说明的
检查／报告规则，历史处理策略的相对收益能否发生可预测的反转？

例如旧分配A→red、B→blue、C→green、D→yellow，报告C失败：

- 按顺序检查到首错就停：A、B通过是可保留的证据。
- 事先独立抽查C：A、B没有通过认证，不能由其未报错推断正确。

因此，“只保留错误项”在前一种规则下丢失证据；“保留报错前缀”
在后一种规则下可能伪造证据。CPU预览已经核对这种逻辑差别，但
这不是新的数学发现，更不是模型的已观察失效。

潜在贡献必须落在**模型如何把失败记录转换成可用记忆，以及这种
转换是否解释处理策略在真实修复中的成败**。仅复现强／弱采样，
仅使一个提示更清楚，或仅在三类同构构造上取得高分，都不够。

## 能改变研究判断的辨别设计

此处记录设计，不提交题单、队列或模型请求。

固定求解模型，比较两种已公开说明的报告规则；每种规则比较：

- 原始失败方案、错误报告与规则说明；
- 按该规则编译的信息等价证据记录。

两者都要评价仍可复用的部分和已经否定的部分，不能只看整条方案
是否重复。先记录模型推断哪些检查已经通过、哪些未被检查，再
让模型真实修复；事实读出本身会改变上下文，故应与修复分支分开，
不能把额外读出当作无影响的测量。这里也不把自述当内部表示证据。

信息等价必须依实际检查器证明；确定性环境可比较一致世界集合，
随机报告环境还需比较似然／后验，只有相同支持集合并不足够。
不能给摘要添加原始记录无法推出的正确答案。真实SQL报错没有
通用的文字前缀认证性质，不能套用玩具环境的首错规则。

值得继续的结果应同时具备：

1. 原始记录中的错误可以定位到证据转换，而非基本任务不会解；
2. 错误转换能预测后续保留或丢弃哪些构造，以及实际修复损伤；
3. 信息等价的规则感知转换同时改善证据使用与真实修复，并在
   未用于发现的结构、至少另一种实际检查语义上保留方向。

这只是资格条件，不是预定会得到的结果。若原始记录已被可靠理解，
若摘要仅带来一般易读性收益，或效果只来自更多答案信息，则不能
支持该机制。若只得到已知的反馈泛化或采样偏差，停止此路线。

## 当前决定

### CPU决策核对后的进一步修正

新增入口：`python scripts/audit_feedback_decision_identifiability_20261012.py`。
原始结果：`outputs/generation-diagnostics-20261005/feedback_evidence_preview/decision_identifiability.json`。
纯CPU精确分数计算，不调用模型。仍是三个同构类别，不能把552条
枚举当独立研究样本。

**当前四角色材料不能直接支持所设想的单次修复收益反转。**在均匀
24个隐藏对应、一次完整分配严格判对的目标下，对所有两种报告规则
均能产生的首错记录，限制保留旧前缀并不会降低最优单次成功概率。
以第三项报错为例，首错规则下允许世界唯一，保留与不限制前缀的
最优成功概率均为1；独立抽查下18个世界等可能，两类策略均为1/18。
前缀未经认证，并不意味着限制它就必然损伤这个单次决策目标。
这不是LLM表现，也不适用于所有抽查事件或多轮修复。

**固定旧方案和报错的配对还存在选择分布问题。**若先从首错记录
构造题，再仅把说明改为独立抽查，则样本中的旧前缀实际上总是正确。
但在如实生成的独立抽查失败事件中，前缀全部正确仅占552/1728，
即23/72。拿被选择的配对样本评价真实修复或概率校准，会把数据
选择偏差混入报告规则效应。完整世界与可见报错完全配对可用于某些
受控推理问题，但不能假装其经验分布就是所声明的抽查过程。

因此撤回“现有玩具材料已经给出修复策略收益反转预测”的隐含推断，
不据此提交GPU实验。不同报告规则包含不同信息仍成立；它本身不
证明特定策略对当前目标有损，更不证明新增模型机制。

若以后重启该候选，必须先选定实际修复目标和如实生成的报告过程，
证明理想策略下的可分辨效应，同时防止把正常信息量差异误认作模型
失效。目前不继续追加玩具变体，也不将换成多轮目标当成自动扩题理由。

- 广义“反馈作用域失效”降级为文献背景，不启动SQL小矩阵。
- “报告规则决定有效记忆”的交互问题保留为待评估候选，不标为
  已确认research gap或用户批准的新主线。先判断真实任务和可分辨
  证据是否够强，再考虑计算；不因为已写下设计就自动执行。
- 现有Game24二元反馈实验没有操纵报告规则。旧轨迹不能补出这一
  对照，也不能以旧head、identity或反馈解码结果替代它。
- 原论文逐题输出无法取得，不再依赖该数据。共享24 GPU小时已
  耗尽，本轮只有文献阅读和设计取舍，没有新增模型调用。

项目目标仍未达成。当前有排除低创新性路线的新依据，尚无足以
支撑ICLR的新机制或稳定MVP。
