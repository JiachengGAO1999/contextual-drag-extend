# Contextual Drag 扩展研究：师兄审阅入口

截至 2026-10-22。这是一份研究过程与证据快照，供方向判断和方法审阅；不是投稿定稿。当前没有正在自动扩展的机制实验。

## 先看这个判断

**新题上已确认行为效应；内部机制尚未识别。** 我们在单 Qwen3-8B 筛选分布上获得 102 道独立合格 Game24 题，完成 R0/R2/R3 共 612 次生成。事前冻结的 82 题独立确认：错误历史使准确率下降约 29.9 个百分点，晚期阻断对错误草稿的直接访问可恢复约 24.4 个百分点。增加样本加强了行为结论，没有自动解决旧机制实验的识别问题。

建议阅读顺序：本页 → [全题集结果](../../docs/game24_100q_8b/FULL_REPLICATION_RESULTS_20261022.md) → [机制条件与竞争解释](../../docs/game24_100q_8b/MECHANISM_READINESS_20261022.md) → [此前特异性审计](../../docs/causal_specificity_evidence_audit_20261013.md)。[GUIDE](../../GUIDE.md) 是完整执行历史，包含已经被后续状态覆盖的旧记录。[texts](../../texts) 保留历史论文材料，尚未按本轮 102 题更新，不应将旧稿中的贡献表述当作当前已经证实的结论。

## 做了什么、证据有多强

数据准备：排除 207 道历史暴露题，筛选 720 道新候选，每题固定 8 次 Qwen3-8B 回答，共 5,760 条。资格要求完整 cohort，至少 2 条正确与 2 条完整实质错误；截断、无法判分、抽取异常不自动算错误见证。最终得到 102 道合格题，文件名仍为 `game24_eligible_100.jsonl`。以 seed 20261014 事前冻结 20 development / 82 held-out。使用单 8B anchor 是本项目明确采用的改编协议，不是原论文多 anchor 筛选的严格复现。

| 条件 | 操作 |
|---|---|
| R0 | 无历史，独立求解 |
| R2 | 完整失败草稿及明确错误反馈，正常继续访问 |
| R3 | 与 R2 的文本、输入 token、位置和完整 prefill 相同；从预测第 2 个生成 token 起阻断对草稿 KV 的直接 attention |

每题固定一份失败草稿、两个配对 seed（927001/927002）。R3 不删除文本，也没有清除所有间接历史信息。源草稿注入最终回答正文，包含解题过程；原始 Thinking 另外保存。实验用 vLLM 0.11.0 / PyTorch 2.8.0 / Transformers 4.55.4，BF16，temperature 0.6、top_p 0.95、top_k 20，最长上下文 32768。开发集在 A100、确认集在 A800；16 个旧请求的前 4-token 跨硬件一致，不代表完整随机轨迹逐位一致。

| 范围 | R0 | R2 | R3 | R3−R2，题目 bootstrap 95% CI |
|---|---:|---:|---:|---:|
| 历史 23 题 8B | 40/46 | 18/46 | 36/46 | +39.1 pp [23.9,54.3] |
| 新 20 题 development | 27/40 | 13/40 | 24/40 | +27.5 pp [10.0,47.5] |
| **新 82 题独立确认（主结果）** | **104/164** | **55/164** | **95/164** | **+24.39 pp [13.41,35.37]** |
| 新 102 题全池描述 | 131/204 | 68/204 | 119/204 | +25.00 pp [14.71,35.29] |

82 题 R0−R2 为 +29.88 pp [18.90,40.85]；R2→R3 有 62 次恢复、22 次损伤。全池为 77 次恢复、26 次损伤。全部截断和无法判分保留分母：全池 20 条截断、11 条无法判分，二者有重叠。统计单位是题目，先平均题内两个 seed，再做 5,000 次 bootstrap；204 个回答对不是 204 道独立题。新旧筛选及题目难度不同，不能把点估计缩小直接归因于 scale。

全池 204 对 R2/R3 的输入与首 token 不变量通过，原始结果 CPU 复算与冻结分析一致。确认集 254 条判对回答的最终式再次精确检查，未发现算术或用数不一致。数据准备累计约 39.05 GPU 小时，两个生成阶段合计约 78.74 小时。完整流程与边界见 [采集报告](../../docs/game24_100q_8b/GAME24_100Q_ACQUISITION_REPORT.md)、[开发协议](../../docs/game24_100q_8b/REPLICATION_PLAN_20261017.md)、[确认协议](../../docs/game24_100q_8b/FULL_REPLICATION_PLAN_20261019.md)。

## 不应被 scale 覆盖的旧结果

| 探索 | 结果与约束 |
|---|---|
| [24 题因果特异性](../../docs/causal_specificity_evidence_audit_20261013.md) | FULL/CANDIDATE/CONTROL 正确数 9/17/16；候选相对控制 +4.17 pp，CI [−16.67,25]，优势未确认。这里是 value 贡献扣除，不能与 R3 attention mask 混为同一算子。 |
| [来源分区重放](../../docs/source_partition_results_20261011.md) | 未支持预期的 GENERATED 优势；几何相似不能证明内容转移。 |
| [Late Invalidation Goal 1](../../docs/late_invalidation_goal1_results_20261012.md) | clean 测量能力未过预定门槛，STOP；没有继续 PRE/POST 或 KV transplant。不能解释为已推翻“识错但不撤销路径”。 |
| [历史主结果及外部边界](../../docs/quick_validation/iclr2027_full_results_and_paper_map_20260925.md) | R3/R4 无稳定更早阻断增益；正确历史和无初始 drag 的外部任务上，阻断可能损伤。 |

“模型识别了错误却未撤销旧路径”仍是研究命题，外部明确告知错误并不等于内部识错已被测量。候选 head 的收益、旧控制有效、短测量失败都不能单独确立新机制。

## 我目前倾向的下一步

已有材料最突出的事实是错误类型集中：实际注入的 102 份草稿中，99 份最终式算值为 24 但违反四个输入数的多重集约束；完整合格错误池 299 条中有 291 条属于这一类。全池 R0/R2/R3 输出中的同类错误为 63/129/71（各 204 次）。这是最终式的 CPU 形态描述，**还不是内部“资源绑定表征”的证据**；一般准确率变化也会减少主导错误类型。

目前值得问的是：**失败历史如何影响后续计算对四个输入数的约束使用？** 先区分三个解释，再决定是否值得做一次新 GPU 实验：

| 竞争解释 | 必须产生的区别性预测 |
|---|---|
| 旧最终式或结构复用 | 改变被复用的具体旧式，应按内容改变后续采用对象；需要超越字符串相似。 |
| 中间计算复用时丢失资源来源 | 即使没有复写旧最终式，也会重组不相容的资源；中间数值相同而资源来源不同，应预测合法性及内容特异的干预方向。 |
| 一般上下文干扰或计算扰动 | 收益不稳定跟随指定内容语义；须与上面两类内容预测比较，不能只看总准确率。 |

推进顺序：先冻结一份有边界的自然轨迹语义审阅方案，覆盖恢复、损伤和未恢复，利用已有同题多草稿，判断是否能找到可测量、可干预且桥接自然错误的对象。若能找到，只设计一个足以让竞争解释产生不同结果的实验；若要作表征干预，应预测内容相关的双向转变，并保留数值与无关资源控制。编号提示、head 排名或总体准确率提高本身不足以构成贡献。

退出条件：找不到自然轨迹中的目标对象；测量本身不可靠；内容改变不产生预测的差异；或一般扰动即可解释结果。出现这些情况就收窄或放弃解释，不靠扩大层、窗口、seed 维持原故事。资源身份与同值异源材料和旧探索有重叠，新颖性尚未完成专门文献核验。82 题已用于本轮确认，不能再称为未查看的新机制验证集。

## 希望师兄重点判断

1. 这份行为复验是否足以作为机制探索基础？筛选偏差、两个 seed、跨硬件或评分边界中，哪一点最影响判断？
2. “中间数值与资源来源的绑定”有解释价值和新颖性吗，还是任务特定的约束跟踪？有没有更有价值的机制对象？
3. 什么最小因果检验能真正区分三个解释，而不是只获得又一个准确率增益？什么结果应让我们停止？
4. 值得投入一个新机制 gate，还是应停在行为复验并换问题？当前没有预设必须写成论文。

git clone --branch review/contextual-drag-102q-20261022 https://github.com/JiachengGAO1999/contextual-drag-extend.git
cd contextual-drag-extend
python review/20261022/verify.py --restore
